kubectl generators

Add $do (--dry-run=client -o yaml) to any create command to get YAML instead of an object.

Create

ObjectCommand
Podk run p --image=nginx:1.27 --labels=app=p --port=80
k run p --image=busybox:1.36 --command -- sleep 3600
Deploymentk create deploy d --image=nginx:1.27 --replicas=3
Servicek expose deploy d --port=80 --target-port=8080 --type=NodePort
expose copies the Deployment's selector. k create svc uses app=<name> instead.
Jobk create job j --image=busybox:1.36 -- date
CronJobk create cj c --image=busybox:1.36 --schedule='*/15 * * * *' -- date
ConfigMapk create cm c --from-literal=K=V --from-file=app.conf
Secretk create secret generic s --from-literal=K=V
ServiceAccountk create sa runner
Rolek create role r --verb=get,list --resource=pods
RoleBindingk create rolebinding rb --role=r --serviceaccount=NS:runner
ResourceQuotak create quota q --hard=pods=5,requests.cpu=1
Ingressk create ingress i --rule='host/api*=svc:80'
A path ending in * is Prefix. Without it, the path is Exact.

Change a live object

Imagek set image deploy/d nginx=nginx:1.27
Replicask scale deploy/d --replicas=4
Resourcesk set resources deploy/d --requests=cpu=100m,memory=64Mi --limits=cpu=200m,memory=128Mi
Rolloutk rollout status|history|undo deploy/d
Anything elsek edit deploy/d. A Pod's spec is mostly immutable: k get pod p -o yaml > p.yaml, edit, then k replace --force -f p.yaml.

No generator: use explain or the docs

Probes, securityContext, volumes, init and sidecar containers, envFrom, NetworkPolicy, PersistentVolumeClaim.

k explain pod.spec.containers.livenessProbe --recursive | less
